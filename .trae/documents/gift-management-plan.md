# 礼品商超管理功能实施计划

## Context
当前礼品只来自预置数据，管理员无法维护礼品。本次在现有规则配置中心增加礼品新增、编辑、删除和上下架能力，并让学员商城实时同步；不引入后端，继续复用全局状态与 localStorage 持久化，同时保护已有订单、积分和阶梯奖励记录。

## 实施方案

### 1. 礼品模型与旧数据兼容
- 修改 `src/lib/domain.js`：默认礼品增加 `isOnShelf: true`，新增 `validateGiftForm`，校验名称、类型、兑换积分、图片地址、说明、实物库存/预算、虚拟头像属性及解锁条件。
- 修改 `src/state/AppContext.jsx` 的 `loadState`：旧礼品缺少 `isOnShelf` 时按上架处理，不合并或重建整个礼品数组，避免已删除礼品刷新后复活，也不影响现有用户数据。
- 新礼品保存 `id`、`createdAt`、`updatedAt`；编辑保留原 ID、类型、`custom` 和上下架状态。礼品类型在新增时确定，避免改动历史订单和虚拟权益语义。

### 2. 状态接口与兑换安全
- 在 `src/state/AppContext.jsx` 增加并导出 `saveGift`、`deleteGift`、`setGiftShelf`，均校验管理员权限。
- 新增/编辑支持名称、积分、图片 URL、说明、解锁条件；实物支持库存和 100 元以内预算，虚拟礼品支持是否兑换后应用头像。保存后立即持久化并同步各页面。
- 上下架只切换状态和更新时间，不清库存、不取消订单、不退款、不解除阶梯关联。
- 删除采用保守策略：被任意订单、当前阶梯或学员虚拟权益引用的礼品禁止硬删除，提示先下架；无引用礼品经二次确认后删除，避免订单驳回无法恢复库存或阶梯产生悬空引用。
- `redeemVirtual`、`redeemPhysical` 增加礼品类型和上下架校验，下架后即使旧详情弹层仍打开，也不能扣积分、减库存或生成订单。

### 3. 管理后台礼品管理
- 修改 `src/pages/Admin.jsx`，新增“礼品管理”Tab。
- 礼品列表展示缩略图、名称、类型、积分、库存/预算、解锁条件和上架状态，提供新增、编辑、上架/下架、删除操作。
- 复用 `Field`、`Sheet`、`Modal`、`Badge`、`ImageWithFallback` 及现有后台按钮/表单模式；新增和编辑共用表单，非法输入就地提示，删除使用确认弹层。
- 阶梯编辑的礼品下拉保留全部礼品，下架项明确标注“已下架”，避免已有关系显示异常。
- 修改 `src/styles.css`，只补充礼品管理列表、缩略图、状态与操作区的局部样式，沿用当前移动端设计。

### 4. 学员端实时同步
- 修改 `src/pages/Shop.jsx`：全部/虚拟/实物筛选只显示上架礼品；下架后关闭或失效已打开的详情与虚拟兑换确认框，并为兑换处理增加空值保护。
- 修改 `src/pages/Home.jsx`：首页“件好礼”只统计上架礼品。
- 历史订单、订单审核、规则页、积分页和已解锁阶梯不按上下架过滤，确保既有记录不受影响；无需新增路由。

## 验证与交付
1. 执行 `npm run build`，确认无编译错误。
2. 浏览器验证新增虚拟/实物礼品、编辑各字段、非法值拦截、上下架、删除确认及刷新后的持久化。
3. 验证下架后商城与首页数量同步、无法继续兑换；重新上架后按原库存和解锁规则恢复兑换。
4. 验证有订单/阶梯引用的礼品删除被拦截，无引用礼品可删除；已有待审核订单仍可审核，驳回仍正常退积分和恢复库存。
5. 更新 Android `versionCode`/`versionName`，同步 Capacitor 资源并重新构建、签名、校验 APK，交付可覆盖安装的新版本。
